# Linly-Talker 部署文档

## 1. 项目概述

Linly-Talker 是一个多模块数字人对话系统，集成了 LLM、ASR、TTS、语音克隆和数字人驱动能力，当前项目中主要包含以下运行入口：

- `webui.py`：综合 WebUI，支持多模型、多模块切换
- `app.py`：基础版 Gradio 对话入口
- `app_talk.py`：图片/视频驱动数字人生成入口
- `api/tts_api.py`、`api/llm_api.py`、`api/talker_api.py`：拆分式 FastAPI 服务

## 2. 推荐运行环境

- 操作系统：Linux 优先，Windows 也可运行
- Python：`3.10`
- CUDA：建议 `11.8`、`12.1` 或 `12.4`
- 显卡：建议 NVIDIA GPU，显存越大越适合加载更多模型
- 依赖管理：`conda + pip`

## 3. 部署目录

部署目录为当前项目根目录：

- `数字人1/研发/Linly-Talker-main/Linly-Talker-main`

以下命令默认在该目录执行。

## 4. 环境创建

```bash
conda create -n linly python=3.10 -y
conda activate linly
```

安装 PyTorch，按本机 CUDA 版本选择其一：

```bash
# CUDA 11.8
pip install torch==2.4.1 torchvision==0.19.1 torchaudio==2.4.1 --index-url https://download.pytorch.org/whl/cu118

# CUDA 12.1
# pip install torch==2.4.1 torchvision==0.19.1 torchaudio==2.4.1 --index-url https://download.pytorch.org/whl/cu121

# CUDA 12.4
# pip install torch==2.4.1 torchvision==0.19.1 torchaudio==2.4.1 --index-url https://download.pytorch.org/whl/cu124
```

可选基础工具：

```bash
python -m pip install --upgrade pip
```

## 5. 安装项目依赖

WebUI 依赖：

```bash
pip install -r requirements_webui.txt
```

轻量应用依赖：

```bash
pip install -r requirements_app.txt
```

如果要启用 MuseTalk 相关能力，继续安装：

```bash
pip install --no-cache-dir -U openmim
mim install mmengine
mim install "mmcv==2.1.0"
mim install "mmdet>=3.1.0"
mim install "mmpose>=1.1.0"
```

如果要启用 NeRF 类能力，还需要：

```bash
pip install -r TFG/requirements_nerf.txt
```

## 6. 模型与资源准备

项目包含多个能力模块，模型按功能分别准备：

- LLM：如 `Qwen/Qwen-1_8B-Chat`
- ASR：如 Whisper、FunASR、OmniSenseVoice
- TTS：EdgeTTS、PaddleTTS、GPT-SoVITS、CosyVoice
- 数字人驱动：SadTalker、Wav2Lip、Wav2Lipv2、MuseTalk、NeRFTalk

默认配置见 `configs.py`，其中包含：

- `port = 6006`
- `ip = '127.0.0.1'`
- `mode = 'offline'`
- `model_path = 'Qwen/Qwen-1_8B-Chat'`
- SSL 证书路径 `./https_cert/cert.pem` 和 `./https_cert/key.pem`

如果需要浏览器麦克风能力，建议保留 HTTPS 证书配置。

## 7. 启动方式

### 7.1 启动综合 WebUI

```bash
python webui.py
```

适合研发联调、功能体验和多模型切换。

### 7.2 启动基础对话界面

```bash
python app.py
```

适合快速验证 ASR + LLM + TTS + Talker 基础链路。

### 7.3 启动图片/视频驱动入口

```bash
python app_talk.py
```

适合单独验证 TTS 与数字人视频生成。

### 7.4 启动 API 服务

TTS：

```bash
python api/tts_api.py
```

LLM：

```bash
python api/llm_api.py
```

Talker：

```bash
python api/talker_api.py
```

也可使用 FastAPI 开发方式：

```bash
fastapi dev api/tts_api.py --host 0.0.0.0 --port 8001
fastapi dev api/llm_api.py --host 0.0.0.0 --port 8002
fastapi dev api/talker_api.py --host 0.0.0.0 --port 8003
```

## 8. 部署检查

启动后建议确认以下事项：

- 页面是否能正常打开
- LLM 是否能返回文本
- TTS 是否能生成 `answer.wav`
- Talker 是否能生成视频
- `temp`、`output` 等目录是否具备写权限
- GPU 显存是否足够支撑当前模块组合

## 9. 常见问题

### 9.1 显存不足

- 优先使用 `webui.py` 的精简组合
- 暂时关闭 MuseTalk、NeRF、语音克隆等重模块
- 降低 batch size
- 优先使用较小的 LLM 或远程 API 模式

### 9.2 麦克风无法使用

- 检查 HTTPS 证书是否存在
- 检查浏览器授权
- 远程访问时将 `server_name` 配置为可访问地址

### 9.3 模型缺失或首次加载慢

- 先单模块验证
- 按 README 中推荐方式预下载模型
- 将大模型与语音模型分阶段部署，避免一次性全部启用

## 10. 生产部署建议

- 将 WebUI 与 API 服务拆分部署
- LLM、TTS、Talker 分别运行在独立进程或独立容器中
- 使用 Nginx 反向代理 HTTPS
- 对 GPU 任务设置队列，避免并发争抢显存
- 将模型缓存目录挂载到持久化存储
