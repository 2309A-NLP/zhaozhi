# Linly-Talker 优化文档

## 1. 优化目标

Linly-Talker 当前已经具备较完整的多模态能力，但在部署复杂度、资源占用、稳定性和研发维护性上仍有优化空间。本文件聚焦可落地优化项。

## 2. 启动与部署优化

### 2.1 拆分部署

建议将以下模块拆分为独立服务：

- LLM 服务
- TTS 服务
- Talker 服务
- WebUI 服务

收益：

- 降低单进程复杂度
- 避免所有模型同时占用显存
- 便于横向扩容

### 2.2 分环境安装

建议按功能准备多套环境：

- 轻量环境：LLM + EdgeTTS
- 标准环境：LLM + TTS + SadTalker/Wav2Lip
- 高性能环境：MuseTalk / NeRF / GPT-SoVITS / CosyVoice

这样可以减少一次性安装失败和依赖冲突。

## 3. 模型加载优化

### 3.1 默认懒加载

当前部分模块已经使用 `lazy_load=True`，建议推广到全部重模型：

- 首次调用时加载
- 空闲时可释放
- 前端展示当前模块是否已加载

### 3.2 模型缓存管理

建议统一模型目录与缓存目录：

- HuggingFace 缓存单独挂载
- 语音模型与数字人模型分目录管理
- 记录模型版本与来源

### 3.3 默认模型降级

将默认 LLM 从较重模型切换为：

- 更小的 Qwen 版本
- API 模式
- 可选空载模式

收益是页面能更快启动，便于演示和教学。

## 4. 显存与性能优化

### 4.1 控制并发模型数

不要默认同时启用：

- LLM
- ASR
- GPT-SoVITS
- CosyVoice
- MuseTalk
- NeRF

建议通过前端开关按需激活。

### 4.2 调整 batch size

Talker 相关模块可优先降低：

- `batch_size`
- 图像分辨率
- 视频 FPS

在保证可用的前提下降低显存峰值。

### 4.3 增加显存回收

`webui.py` 中已有 `clear_memory()` 思路，建议：

- 在模型切换后执行
- 在任务完成后视情况回收
- 加入 `torch.cuda.is_available()` 判断，避免 CPU 环境报错

## 5. 架构优化

### 5.1 抽离编排层

将 `LLM_response`、`TTS_response`、`Talker_response` 等流程封装到单独服务层或 pipeline 层，避免散落在多个 Gradio 脚本中。

### 5.2 统一配置管理

建议将 `configs.py` 迁移为：

- `yaml` 配置
- `.env` 环境变量
- 命令行参数覆盖

提升多环境部署能力。

### 5.3 统一异常处理

当前部分逻辑采用 `try/except` 后直接提示，建议进一步统一：

- 模块未加载
- 模型文件缺失
- 网络不可达
- 输入参数非法

统一返回结构和日志格式。

## 6. API 优化

### 6.1 增加健康检查接口

建议新增：

- `/health`
- `/ready`
- `/models`

便于外部编排系统检查服务状态。

### 6.2 增加任务化接口

对视频生成等长耗时任务，建议改为：

1. 提交任务
2. 查询状态
3. 拉取结果

避免同步阻塞。

## 7. 前端优化

### 7.1 精简默认页面

默认界面只展示最常用链路：

- 文本输入
- 语音输入
- 模型选择
- 生成结果

其余高级项折叠展示，降低使用门槛。

### 7.2 状态可视化

建议增加：

- 当前加载模型
- GPU 占用
- 当前任务阶段
- 生成耗时

有助于研发定位性能瓶颈。

## 8. 测试与维护优化

### 8.1 增加最小自动化测试

优先补充：

- 配置加载测试
- API 路由测试
- 空输入测试
- 非法模型名测试

### 8.2 增加环境检查脚本

建议新增一键诊断脚本，检查：

- Python 版本
- CUDA 是否可用
- PyTorch 是否可用
- 模型文件是否存在
- 证书文件是否存在

## 9. 优先级建议

建议按以下顺序推进：

1. 拆分部署与统一配置
2. 模型懒加载与显存回收
3. API 任务化与健康检查
4. 自动化测试与日志体系
5. 前端状态可视化
