# Linly-Talker 测试文档

## 1. 测试目标

验证 Linly-Talker 在当前代码结构下的核心链路是否可用：

- ASR 语音识别
- LLM 文本生成
- TTS 语音合成
- Talker 数字人视频生成
- WebUI 页面交互
- API 服务调用

本项目当前更偏向工程集成和人工联调，仓库内没有成体系的自动化单元测试，因此测试以冒烟测试、接口测试和链路测试为主。

## 2. 测试环境建议

- Python `3.10`
- GPU 环境已安装 PyTorch
- 已安装 `requirements_webui.txt` 或 `requirements_app.txt`
- 已准备至少一个可用 LLM/TTS/Talker 模型

## 3. 测试分层

### 3.1 启动测试

验证入口文件可正常启动：

```bash
python app.py
python webui.py
python app_talk.py
```

检查项：

- 启动无语法错误
- Gradio 页面可访问
- 页面组件渲染完整

### 3.2 ASR 测试

测试方式：

- 在页面中上传一段中文语音
- 点击语音识别按钮

检查项：

- 能返回文本结果
- 返回文本为可读中文
- 失败时有错误提示，不出现进程崩溃

### 3.3 LLM 测试

在文本框输入问题，例如：

- 你好，请做一个简短自我介绍
- 请用 20 个字以内回答今天天气如何

检查项：

- 模型能返回文本
- 多轮问答时上下文不会立即失效
- 模型切换后仍可返回结果

### 3.4 TTS 测试

分别验证：

- EdgeTTS
- PaddleTTS
- GPT-SoVITS
- CosyVoice

检查项：

- 能生成音频文件
- 音频文件时长与文本大致匹配
- 非法参数时能提示错误
- 语音克隆模式缺少参考音频时能阻断并提示

### 3.5 数字人生成测试

分别验证：

- SadTalker
- Wav2Lip
- Wav2Lipv2
- NeRFTalk

输入：

- 一张人物图片
- 一段 TTS 生成音频

检查项：

- 能生成视频文件
- 口型与音频基本同步
- 批量大小调整后不会直接报错
- 不支持的方法会返回明确提示

### 3.6 API 测试

项目自带客户端脚本，可按模块测试：

```bash
python api/tts_client.py
python api/llm_client.py
python api/talker_client.py
```

检查项：

- `/docs` 页面可访问
- 接口返回状态正常
- 输出文件能落盘到 `output` 目录

## 4. 推荐测试用例

### 用例 1：基础文本到音频

步骤：

1. 启动 `webui.py`
2. 输入短文本
3. 选择 EdgeTTS
4. 生成音频

预期：

- 成功输出 `answer.wav`

### 用例 2：文本到数字人视频

步骤：

1. 启动 `app.py`
2. 输入文本问题
3. 提交生成

预期：

- 先生成文本和语音
- 再生成可播放视频

### 用例 3：上传语音驱动问答

步骤：

1. 上传一段语音
2. 执行 ASR
3. 提交生成数字人回答

预期：

- ASR 结果可读
- 最终视频可播放

### 用例 4：API 独立联调

步骤：

1. 启动 `api/tts_api.py`
2. 运行 `api/tts_client.py`

预期：

- 能正常生成语音
- 返回值结构符合接口文档

## 5. 异常测试

建议覆盖以下场景：

- 未加载模型直接调用
- 上传空音频
- 文本为空
- 使用不受支持的模型名称
- GPU 显存不足
- 证书文件缺失

预期：

- 服务应尽量给出提示，而不是直接退出

## 6. 性能测试建议

关注以下指标：

- 页面首次启动时间
- 模型首次加载时间
- 单次 TTS 耗时
- 单次视频生成耗时
- GPU 显存峰值

建议分别测试：

- 轻量模式：仅 LLM + EdgeTTS
- 标准模式：LLM + TTS + SadTalker
- 重载模式：语音克隆 + MuseTalk / NeRF
