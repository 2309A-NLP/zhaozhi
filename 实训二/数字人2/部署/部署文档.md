# LiveTalking 部署文档

## 1. 项目概述

LiveTalking 是一个实时流式数字人引擎，强调低延迟音视频同步、可打断对话和多传输方式输出。当前项目核心入口为：

- `app.py`：主服务入口
- `config.py`：CLI + YAML 配置解析
- `server/`：WebRTC、路由、会话、任务管理
- `avatars/`：数字人模型实现
- `tts/`：语音合成插件
- `streamout/`：输出通道

## 2. 推荐运行环境

根据项目 README，推荐：

- 操作系统：Ubuntu 22.04 优先
- Python：`3.12+`
- PyTorch：`2.9.1`
- CUDA：`13.0`

也可在 Windows / macOS 进行功能开发，但实时推流和 GPU 推理优先建议 Linux。

## 3. 部署目录

当前部署目录为：

- `数字人2/研发/LiveTalking-main/LiveTalking-main`

以下命令默认在该目录执行。

## 4. 环境安装

```bash
conda create -n livetalking python=3.12 -y
conda activate livetalking
```

安装 PyTorch：

```bash
pip install torch==2.9.1 torchvision==0.24.1 torchaudio==2.9.1 --index-url https://download.pytorch.org/whl/cu130
```

安装项目依赖：

```bash
pip install -r requirements.txt
```

如果需要读取 `.env`，可以在项目根目录放置环境变量文件。

## 5. 模型与资源准备

最小运行 `wav2lip` 模式需要准备：

1. 将 `wav2lip256.pth` 放入 `models/` 并重命名为 `wav2lip.pth`
2. 将 `wav2lip256_avatar1.tar.gz` 解压后放入 `data/avatars/`

根据所选模型不同，准备对应 avatar 资源：

- `wav2lip`
- `musetalk`
- `ultralight`

## 6. 启动方式

### 6.1 WebRTC 模式

```bash
python app.py --transport webrtc --model wav2lip --avatar_id wav2lip256_avatar1
```

### 6.2 RTMP 模式

```bash
python app.py --transport rtmp --model wav2lip --avatar_id wav2lip256_avatar1
```

### 6.3 虚拟摄像头模式

```bash
python app.py --transport virtualcam --model wav2lip --avatar_id wav2lip256_avatar1
```

### 6.4 使用配置文件启动

```bash
python app.py --config config.yaml
```

`config.py` 支持：

- 命令行参数
- YAML 配置
- CLI 覆盖 YAML 默认值

## 7. 关键启动参数

常用参数包括：

- `--model`：`musetalk` / `wav2lip` / `ultralight`
- `--avatar_id`：数字人资源 ID
- `--batch_size`：推理 batch
- `--tts`：TTS 插件类型
- `--transport`：`webrtc` / `rtmp` / `virtualcam` / `rtcpush`
- `--max_session`：最大会话数
- `--listenport`：监听端口，默认 `8010`

## 8. 网络与端口要求

WebRTC 场景至少需要关注：

- TCP：`8010`
- UDP：媒体传输端口范围

如果运行在云主机或容器中，需要确认：

- 安全组放通端口
- 宿主机支持 UDP
- NAT / TURN / SRS 配置符合网络环境

## 9. 访问方式

启动后可访问：

- 首页：`/index.html`
- Avatar 生成页：`/avatar.html`
- 管理页：`/admin.html`

常用 API：

- `POST /offer`
- `POST /human`
- `POST /humanaudio`
- `POST /record`
- `GET /record/{sessionid}`

## 10. 部署检查

建议按以下顺序确认：

- 页面能否打开
- `app.py` 是否完成模型预热
- WebRTC 是否能建立会话
- 文本驱动是否能说话
- 音频驱动是否能播放
- 录制文件是否能下载

## 11. 常见问题

### 11.1 模型无法加载

- 检查 `models/` 和 `data/avatars/` 资源是否齐全
- 检查 `--model` 与 avatar 类型是否匹配

### 11.2 WebRTC 连不上

- 检查端口是否放通
- 检查 UDP 是否可用
- 云端环境必要时补充 TURN / SRS

### 11.3 并发不足

- 提高 GPU 规格
- 下调分辨率或 batch size
- 调整 `--max_session`

## 12. 生产部署建议

- 按模型类型分机部署
- 使用 Nginx 或 API Gateway 统一入口
- 将会话、任务、日志独立存储
- 为实时服务增加监控与告警
- 将模型与 avatar 资源挂载到持久化目录
