# LiveTalking 测试文档

## 1. 测试目标

验证 LiveTalking 的实时数字人服务在以下方面可正常运行：

- 服务启动与模型预热
- WebRTC 建链
- 文本驱动说话
- 音频驱动播放
- 录制与回放
- 多会话管理
- 管理接口与任务接口

## 2. 测试环境

- Python `3.12+`
- 已安装 `requirements.txt`
- 已准备数字人模型文件和 avatar 数据
- 建议使用带 GPU 的 Linux 环境

## 3. 测试分类

### 3.1 启动测试

执行：

```bash
python app.py --transport webrtc --model wav2lip --avatar_id wav2lip256_avatar1
```

检查项：

- 服务进程正常启动
- 控制台无立即退出错误
- 首页 `http://<host>:8010/index.html` 可访问

### 3.2 WebRTC 建链测试

步骤：

1. 打开浏览器首页
2. 点击开始连接
3. 建立会话

检查项：

- `/offer` 返回 `answer` 和 `sessionid`
- 浏览器端能建立音视频连接
- 连接失败时服务端日志有可定位信息

### 3.3 文本驱动测试

调用方式：

- 浏览器页面输入文本
- 或调用 `POST /human`

建议测试文本：

- 你好，请做一个简短介绍
- 请用一句话介绍本系统

检查项：

- 服务能接收文本
- 数字人能开口说话
- `type=echo` 与 `type=chat` 两种模式都能工作

### 3.4 音频驱动测试

调用：

- `POST /humanaudio`

检查项：

- 上传音频可被服务接收
- 数字人能根据音频驱动口型
- 非法文件会被拒绝或报错明确

### 3.5 打断测试

调用：

- `POST /interrupt_talk`

检查项：

- 正在播报时可被立即打断
- 打断后可继续接收新任务

### 3.6 录制测试

调用顺序：

1. `POST /record`，`type=start_record`
2. 触发一段说话任务
3. `POST /record`，`type=end_record`
4. `GET /record/{sessionid}`

检查项：

- 录制文件生成成功
- 下载返回 MP4 文件

### 3.7 会话与并发测试

关注：

- `--max_session` 限制是否生效
- 超出上限时是否返回明确错误
- 多个 `sessionid` 之间是否相互隔离

### 3.8 Avatar 任务测试

如启用生成接口，测试：

- avatar 创建
- 进度查询
- 删除任务

重点验证：

- 任务状态流转
- 失败后的异常提示

## 4. 接口测试建议

建议至少覆盖以下接口：

- `POST /offer`
- `POST /human`
- `POST /humanaudio`
- `POST /interrupt_talk`
- `POST /is_speaking`
- `POST /record`
- `GET /record/{sessionid}`

验证内容：

- 返回码是否符合文档
- 参数缺失时是否能报错
- 会话不存在时是否能提示

## 5. 性能测试建议

重点观察两个指标：

- `inferfps`
- `finalfps`

文档建议两者尽量都不低于 `25`。

建议分模型测试：

- `wav2lip`
- `musetalk`
- `ultralight`

建议分显卡记录：

- GPU 型号
- 单路实时 FPS
- 最大并发会话数
- CPU 占用
- 显存峰值

## 6. 稳定性测试建议

建议长时间运行验证：

- 连续运行 2 小时以上
- 连续创建和释放会话
- 持续录制
- 持续打断与重播

检查项：

- 内存是否持续上涨
- 会话是否泄漏
- 录制文件是否异常

## 7. 回归测试建议

每次升级以下内容后应回归：

- Avatar 模型
- TTS 插件
- WebRTC 逻辑
- 路由与任务管理
- 配置文件
