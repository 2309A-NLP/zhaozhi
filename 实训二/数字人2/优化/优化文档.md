# LiveTalking 优化文档

## 1. 优化目标

LiveTalking 已具备较完整的实时数字人服务能力，优化重点应放在：

- 实时性
- 并发能力
- 稳定性
- 可扩展性
- 可运维性

## 2. 性能优化

### 2.1 模型分级部署

建议按模型类型拆分节点：

- `wav2lip` 节点
- `musetalk` 节点
- `ultralight` 节点

收益：

- 避免不同模型互相争抢显存
- 便于按业务量独立扩容

### 2.2 预热优化

当前启动阶段已经执行 `warm_up`，建议继续优化：

- 预热后记录实际首帧耗时
- 不同 batch size 分别预热
- 将预热结果输出到日志

### 2.3 批量与分辨率调优

重点调节：

- `--batch_size`
- avatar 分辨率
- 输出帧率

目标是在 `inferfps` 和 `finalfps` 达标前提下，尽可能提升并发。

## 3. 会话与并发优化

### 3.1 动态会话上限

当前 `--max_session` 为固定值，建议改为根据 GPU 型号、模型类型和分辨率动态估算建议值。

### 3.2 会话回收

需要重点关注：

- 断开连接后的资源回收
- 空闲 session 超时释放
- 录制结束后的文件和句柄释放

### 3.3 全局缓存策略

`global_avatars` 可以减少重复加载，但也可能扩大常驻内存。建议：

- 设置缓存上限
- 记录最近使用时间
- 对冷 avatar 做回收

## 4. 架构优化

### 4.1 启动逻辑下沉

建议将 `app.py` 中的以下逻辑继续拆分：

- 配置解析
- 模型装配
- 服务装配
- 传输装配

拆成独立模块后更利于测试和维护。

### 4.2 引入服务健康检查

建议新增接口：

- `/health`
- `/ready`
- `/metrics`

用途：

- 容器探针
- 监控采集
- 发布后巡检

### 4.3 鉴权与访问控制

当前接口更偏内网研发使用，若对外开放，建议增加：

- Token 鉴权
- 管理端权限控制
- 会话级别访问控制
- CORS 白名单

## 5. 输出链路优化

### 5.1 按场景选择传输方式

建议：

- 浏览器交互优先 `webrtc`
- 直播平台推流优先 `rtmp`
- 本地桌面集成优先 `virtualcam`

避免一个场景内混用多种输出方式增加排障成本。

### 5.2 网络适配

WebRTC 场景建议补充：

- TURN 支持
- NAT 场景测试
- 公网弱网环境下的降级策略

## 6. 插件体系优化

### 6.1 标准化插件接口

当前注册机制已具备基础能力，建议继续统一：

- 输入参数规范
- 输出结果规范
- 错误码规范

便于团队新增插件时保持一致。

### 6.2 插件配置外置

将 TTS、Avatar、Output 的默认配置从代码移到 YAML，可减少改代码部署。

## 7. 日志与监控优化

建议重点监控：

- 建链成功率
- 活跃会话数
- TTS 耗时
- 推理耗时
- `inferfps`
- `finalfps`
- GPU 显存占用
- 录制成功率

同时建议统一日志字段，便于检索和报警。

## 8. 测试优化

建议优先增加自动化测试：

- `config.py` 参数解析测试
- `registry.py` 插件注册测试
- 路由参数校验测试
- 会话上限测试
- 录制接口测试

对实时链路则保留集成测试和压测。

## 9. 运维优化

建议增加：

- 一键环境检查脚本
- 一键模型检查脚本
- 发布前自检脚本
- GPU 资源巡检脚本

这样可以明显降低部署和排障成本。

## 10. 优先级建议

推荐按以下顺序推进：

1. 会话回收与监控补齐
2. 健康检查与鉴权
3. 模型节点拆分
4. 插件接口标准化
5. 自动化测试补齐
