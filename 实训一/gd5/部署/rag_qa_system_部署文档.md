# gd5 rag_qa_system 部署文档

## 部署定位
gd5 在 gd3 的解析增强基础上加入了对话记忆能力，部署重点从单轮问答扩展到多轮连续对话。

## 新增关键配置
- `CONVERSATION_MAX_MESSAGES`
- `CONVERSATION_TTL_SECONDS`
- `MIN_CONTEXT_SCORE`
- PDF 清洗参数仍需一起配置

## 部署步骤
1. 完成 MySQL、Redis、Milvus 与模型配置
2. 设置对话保留条数和过期时间
3. 导入至少一份可连续追问的 PDF
4. 启动服务并用多轮问答验证上下文延续

## 部署验收
- 单轮问答可正常工作
- 连续追问时，后续问题可以继承前文上下文
- Redis 中存在与会话相关的缓存或状态数据
- 对话过期后，旧上下文不会持续污染新会话

## 风险提示
- 会话记忆过长会引入噪音上下文
- TTL 过短会让用户感觉“记不住”
- Redis 在这一版中的重要性高于前几版
