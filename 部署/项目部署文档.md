# 角色扮演系统部署文档

## 1. 文档说明

本文档基于当前仓库实际代码整理，适用于本项目的本地部署、测试环境部署和基础生产部署。

当前项目代码主体位于 `研发` 目录，部署时请以 `研发` 作为运行目录。

## 2. 项目组成

项目包含以下几个主要部分：

- 后端服务：`FastAPI`
- 前端入口 1：`FastAPI` 托管的静态页面，访问地址为 `/`
- 前端入口 2：`Streamlit` 工作台，入口文件为 `app/streamlit_app.py`
- 数据存储：默认支持 `SQLite`，也支持 `MySQL`
- 短期记忆：优先使用 `Redis`，不可用时自动回退到进程内存
- 向量检索：优先使用 `Milvus`，不可用时自动回退到本地检索链路
- 大模型调用：兼容 OpenAI 风格接口，也支持通过 `run_vllm.ps1` 启动本地 `vLLM`

## 3. 关键目录与入口

- 项目运行目录：`研发`
- 后端入口：`研发/app/main.py`
- Streamlit 入口：`研发/app/streamlit_app.py`
- 静态前端目录：`研发/frontend`
- 数据库初始化脚本：`研发/init_db.py`
- 本地启动脚本：`研发/run_local.ps1`
- 本地 vLLM 启动脚本：`研发/run_vllm.ps1`
- 环境变量文件：`研发/.env`

## 4. 部署方式建议

### 4.1 快速可运行模式

适合本机调试或先把系统跑起来，推荐组合如下：

- 数据库：`SQLite`
- 后端：`FastAPI`
- 前端：静态前端或 `Streamlit`
- Redis：可不启
- Milvus：可不启
- LLM：在线接口或本地 `vLLM`

这是当前仓库默认最容易跑通的方式，因为现有 `.env` 已经配置了：

```env
DATABASE_URL=sqlite+aiosqlite:///./data/app.db
```

### 4.2 标准服务模式

适合联调、内网部署或正式环境，推荐组合如下：

- 数据库：`MySQL 8.x`
- 缓存：`Redis 6.x/7.x`
- 向量库：`Milvus 2.x`
- 后端：`FastAPI`
- 前端：静态前端和/或 `Streamlit`
- LLM：在线接口或本地 `vLLM`

## 5. 环境要求

建议环境：

- Python `3.10+`
- pip
- Windows PowerShell 或 Linux Shell

可选组件：

- MySQL `8.x`
- Redis `6.x/7.x`
- Milvus `2.x`
- Docker Desktop + NVIDIA 环境（仅在使用本地 `vLLM` 时需要）

## 6. 安装依赖

先进入项目运行目录：

```powershell
cd 研发
```

创建虚拟环境并安装依赖：

```powershell
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

Linux 参考命令：

```bash
cd 研发
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## 7. 环境变量配置

项目会自动读取 `研发/.env`。建议至少检查以下变量。

### 7.1 最小可运行配置

```env
APP_NAME=角色扮演系统
APP_VERSION=1.1.0

DATABASE_URL=sqlite+aiosqlite:///./data/app.db

LLM_BASE_URL=https://api.deepseek.com
LLM_API_KEY=请替换为你自己的密钥
LLM_MODEL=deepseek-chat

BGE_EMBEDDING_MODEL=BAAI/bge-m3
BGE_RERANKER_MODEL=BAAI/bge-reranker-v2-m3
ENABLE_FLAGEMBEDDING=0
ENABLE_FLAGRERANKER=0
EMBEDDING_DIM=1024

SECRET_KEY=请替换为生产密钥
ACCESS_TOKEN_EXPIRE_MINUTES=30
```

### 7.2 MySQL 模式示例

如果你想切到 MySQL，建议去掉 `DATABASE_URL`，改用以下配置：

```env
MYSQL_HOST=127.0.0.1
MYSQL_PORT=3306
MYSQL_USER=root
MYSQL_PASSWORD=你的密码
MYSQL_DATABASE=roleplay_rag
```

也可以直接使用完整连接串：

```env
DATABASE_URL=mysql+asyncmy://root:你的密码@127.0.0.1:3306/roleplay_rag?charset=utf8mb4
```

### 7.3 Redis 配置

```env
REDIS_HOST=127.0.0.1
REDIS_PORT=6379
REDIS_PASSWORD=
```

说明：

- Redis 不是强依赖
- Redis 不可用时，会话短期记忆自动退回进程内存

### 7.4 Milvus 配置

```env
MILVUS_HOST=127.0.0.1
MILVUS_PORT=19530
MILVUS_COLLECTION_NAME=rag_knowledge
MILVUS_CONVERSATION_COLLECTION_NAME=rag_conversations
```

说明：

- Milvus 不是强依赖
- Milvus 不可用时，文档分块仍会落到本地数据库表中
- 检索失败时，系统会自动改用本地检索

### 7.5 Streamlit 对后端地址的配置

`Streamlit` 默认请求：

```env
BACKEND_API_BASE=http://127.0.0.1:8000/api
```

如果前后端不在同一台机器，请把它改成真实后端地址。

### 7.6 本地 vLLM 配置

如果通过 `run_vllm.ps1` 在本机启动 OpenAI 兼容接口，可使用：

```env
LLM_BASE_URL=http://127.0.0.1:8001/v1
LLM_API_KEY=EMPTY
LLM_MODEL=Qwen/Qwen2.5-1.5B-Instruct
```

## 8. 数据库初始化

项目启动时会自动建表，也可以手动执行一次：

```powershell
python init_db.py
```

作用：

- 初始化数据库表结构
- 不会自动创建默认账号

## 9. 启动方式

### 9.1 方式一：只启动 FastAPI

这也是当前静态前端的运行方式。

```powershell
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

启动后可访问：

- 健康检查：`http://127.0.0.1:8000/health`
- 静态前端首页：`http://127.0.0.1:8000/`
- 前端静态资源：`http://127.0.0.1:8000/frontend/`

### 9.2 方式二：使用仓库自带脚本启动本地后端

```powershell
.\run_local.ps1
```

说明：

- 该脚本会在新 PowerShell 窗口中启动 `uvicorn`
- 文案里提到 “FastAPI backend and HTML frontend on http://127.0.0.1:8000”
- 实际上它启动的是后端服务，静态前端由后端根路径托管

### 9.3 方式三：启动 Streamlit 工作台

```powershell
streamlit run app/streamlit_app.py --server.port 8501
```

启动后访问：

- `http://127.0.0.1:8501`

说明：

- `Streamlit` 登录页和工作台依赖后端接口
- 请先确认 `FastAPI` 已经启动

### 9.4 方式四：后端 + Streamlit 同时运行

推荐顺序：

1. 启动 `FastAPI`
2. 确认 `/health` 正常
3. 启动 `Streamlit`
4. 打开 `http://127.0.0.1:8501`

## 10. 本地 vLLM 启动方式

项目提供了 `run_vllm.ps1`，用于通过 Docker 启动本地 OpenAI 兼容模型服务。

示例：

```powershell
.\run_vllm.ps1
```

自定义模型示例：

```powershell
.\run_vllm.ps1 -Model "Qwen/Qwen2.5-7B-Instruct" -Port 8001
```

前提条件：

- 已安装 Docker Desktop
- Docker 可用 GPU
- 主机具备 NVIDIA 运行环境

启动后，把 `.env` 中的 `LLM_BASE_URL` 改成：

```env
LLM_BASE_URL=http://127.0.0.1:8001/v1
```

## 11. 首次使用流程

1. 进入 `研发` 目录
2. 激活虚拟环境
3. 检查 `.env`
4. 安装依赖
5. 执行 `python init_db.py`
6. 启动 `FastAPI`
7. 按需启动 `Streamlit`
8. 打开页面
9. 先注册账号，再登录
10. 创建角色或使用默认角色
11. 上传知识文档
12. 开始对话测试

## 12. 支持的文档与检索说明

支持上传：

- `.txt`
- `.md`
- `.pdf`
- `.docx`

文档处理流程：

1. 上传文件
2. 解析文本内容
3. 按 `CHUNK_SIZE` 与 `CHUNK_OVERLAP` 切块
4. 生成向量
5. 优先写入 `Milvus`
6. 同时把切块信息写入本地数据库表

检索策略：

- 优先走 `Milvus` 混合检索
- `Milvus` 不可用或查询失败时，自动回退到本地检索

```powershell
curl http://127.0.0.1:8000/health
```

预期返回：

```json

```

### 13.3 Milvus 端口检查

```powershell

```

### 13.4 MySQL 端口检查

```powershell
Test-NetConnection 127.0.0.1 -Port 3306
```

### 13.5 部署成功判定

满足以下条件即可认为部署成功：

- `http://127.0.0.1:8000/health` 返回 `ok`
- 可以打开 `http://127.0.0.1:8000/` 或 `http://127.0.0.1:8501`
- 可以注册并登录
- 可以上传文档
- 可以发起问答
- 即使 Redis 或 Milvus 不可用，系统仍能给出降级结果

## 14. 常见问题

### 14.1 后端能启动，但聊天一直超时

优先检查：

- `LLM_BASE_URL` 是否正确
- `LLM_API_KEY` 是否有效
- 外部模型接口是否可达
- `LLM_TIMEOUT_SECONDS` 和 `LLM_HARD_TIMEOUT_SECONDS` 是否过小

### 14.2 Streamlit 页面能打开，但登录失败

优先检查：

- `FastAPI` 是否已经启动
- `BACKEND_API_BASE` 是否正确
- `/health` 是否返回正常
- 数据库是否可连接

### 14.3 文档上传成功，但检索效果不稳定

优先检查：

- `knowledge_domain` 是否选对
- 嵌入模型路径或模型名是否有效
- `ENABLE_FLAGEMBEDDING` 与 `ENABLE_FLAGRERANKER` 是否符合当前环境
- 当前是否在 `Milvus` 模式还是本地回退模式

### 14.4 Redis 没启动是否影响使用

不会阻塞系统启动，但会有这些影响：

- 短期记忆退回进程内存
- 服务重启后，短期会话上下文会丢失

### 14.5 Milvus 没启动是否影响使用

不会阻塞系统启动，但会有这些影响：

- 向量检索退回本地检索
- 大规模数据下检索能力和性能会弱一些

## 15. 生产部署建议

建议：

- 不要在生产环境使用 `--reload`
- 修改 `SECRET_KEY`
- 不要把真实 `LLM_API_KEY` 提交到仓库
- 不要保留开发环境中的绝对本地模型路径
- 如果对外开放，请通过反向代理暴露服务

推荐拆分：

- `/api/*` 转发到 `FastAPI`
- `/` 转发到静态前端
- `Streamlit` 独立端口运行，仅在需要时开放

## 16. 当前项目特别注意项

根据当前仓库实际内容，部署前建议额外处理以下事项：

1. `研发/.env` 中如果保留了真实密钥，请先替换为你自己的安全配置。
2. `BGE_EMBEDDING_MODEL` 和 `BGE_RERANKER_MODEL` 目前可能是开发机绝对路径，换机器后通常需要改成新路径或模型名。
3. 如果只想最快跑通，优先保留 `SQLite` 配置，不要一开始就切 MySQL。
4. 如果只启动了 `FastAPI`，访问 `http://127.0.0.1:8000/` 即可看到静态前端，不需要再额外起前端构建工具。
